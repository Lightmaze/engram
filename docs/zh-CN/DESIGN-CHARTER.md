# Engram开发宪章

[English](../en/DESIGN-CHARTER.md)

> 状态：当前设计合同。它用来判断实现是否仍服务于项目目的，不是人工审阅门，也不是新的治理流程。

## 目的

Engram要解决的不是“怎样检索更多过去”，而是：

> **怎样让一个真实存在过的 Agent 会话，带着自己的完整历史位置重新进入现在，陪伴一段时间，并在不接管当前的前提下产生影响。**

最小运行关系是：

```text
Engram 的完整原始上下文
+ Engram 后来亲历的陪伴历史
+ 明确的唤醒接缝
+ 当前主线程的一段真实对话
→ Engram 自己判断沉默或发言
→ 具名发言进入主线程
→ 后续现场继续被它观察
→ 释放或超时后重新沉睡
→ 在陪伴期间或结束以后，调用者可以把一项具体 Outcome 关联到某次唤醒
→ Engram 自己作出改变或不改变
→ 当前有效的自我折叠进入以后唤醒
```

## Engram 是什么

Engram 是一个可再次运行的历史 Agent 会话。

- 它的“历史身体”首先是原始消息全文，保留原有角色、顺序和内容。
- 它后来真实观察到的主线程消息、自己的回应以及可观察结果，使这段会话继续增长。
- `engram_id` 只是地址；`name` 和 `statement` 只是帮助辨认它的目录信息。
- 每次唤醒或自我折叠都可以向模型提供方发起一个新请求，但运行时必须重新提交连续上下文。“提供方不保存远程状态”不等于“Engram 没有上下文”。

因此，下列对象都不能单独冒充 Engram：

- 一句“你是某某”的身份提示；
- 人格卡或立场摘要；
- 从资料库检索出的几个相似片段；
- 某家模型提供方保存的远程线程编号；
- 一份只供人阅读的 Markdown 档案。

## 唤醒必须满足什么

### 1. 自身上下文完整

唤醒时，原始消息必须作为真正的会话消息装载，不能被改写成摘要、检索材料或一大段引用文本。若完整装载已经不可能，系统必须明确失败或进入未来另行设计的可见换页过程，不能暗中删减后仍声称“完整”。

### 2. 看见当前主线程的一段真实对话

`scene`（现场）不能被默认理解成“最新一句用户提示”。它应是当前主线程的一段有顺序、有说话者的真实对话，必要时包含主 Agent 的回答和工具结果。

不同宿主能提供的范围不同。宿主只能提供较窄片段时，必须把省略写明；不能让 Engram 在只看见一句话时误以为自己理解了当前关系。

### 3. 自己决定沉默或发言

候选选择可以由用户、主 Agent 或 Hook 完成，但最终是否发言必须由已经装载自身上下文的 Engram 判断。`<silent>` 是有效结果，不是检索失败。

### 4. 陪伴不是一次检索

一次召唤开启一个有编号的陪伴期。后续多轮继续沿用同一 `accompaniment_id`：Engram 的回应仍是它自己的回应，主线程的新内容仍是外部观察。释放或空闲超时才结束这段陪伴。

### 5. 发言必须保留归属

Engram 的话进入宿主后，必须仍能辨认“谁说的、从什么历史立场说的、属于哪次陪伴”。归属不是密码学防伪，但不能在显示、持久保存或重新载入时被并入用户或主 Agent 的话。

## 两种入口

- **MCP 召唤：**用户或主 Agent 主动点名一个 Engram。选择权在挥动“法杖”的一方；醒来的 Engram仍自己判断和陪伴。
- **Hook 守护：**宿主在回合边界自动唤醒预先选择的 Engram。自动发生不等于强制发言，Engram 仍可沉默。

MCP 是最小通用接入面；Hook 是拥有宿主生命周期信号后的增强。两者调用的是同一个 Engram，而不是两种不同人格。

## 成长的含义

成长不是把每条模型输出都重新喂给模型，也不是让用户长期担任正确答案审核员。

项目采用以下区分：

- **原始历史：**真实发生的消息，不可由后来摘要覆盖。
- **外部观察：**Engram 在主线程看见了什么。
- **Engram 发言：**它当时作出了什么判断，不自动变成事实。
- **结果与纠正：**后来发生了什么，用户或主线程怎样回应。
- **自我折叠：**Engram 根据这些经历重新组织自己的理解；这次组织会成为下次上下文的一部分。

v0 的最小成长机械是结果驱动的自我折叠。调用者明确把允许使用的后来证据关联到一次具体唤醒；Engram 随即自行决定 `change`（改变）或 `no_change`（不改变），改变会立即成为当前姿态。这是 Engram 自己的更新，不是等待用户审批的提案。用户或宿主仍可纠正、暂停、释放，或者追加回退事件恢复父姿态，而不删除历史。

Outcome 是一项有作用域的因果主张，不是 ground truth（现实中的可靠事实）。运行时会核对本地事件链和声明的来源种类，但不认证 MCP 调用者，不为工具背书，也不核验调用者提交的外部内容。`source_digest` 只记录运行时收到的内容字节的 SHA-256，不是对现实的证明。随后形成的 self-fold 明确由 Engram 创作，权限仅为 `posture/hypothesis`（姿态／假设），永远不能改写成用户发言或用户承诺。

自动守护会保存观察，但不会自行判定哪条观察已经成为 Outcome。定时成长、无来源成长、标量奖励和代际生成机械仍不属于 v0。用户不承担逐条批准 Engram 呼吸与成长的义务，启用伴随也不能制造持续审阅工作。

## 永久边界

1. 当前用户的明确意图高于任何历史判断。
2. Engram 的发言默认只是建议；它不能给自己取得宿主工具和行动权限。
3. 原始消息不能被摘要、索引、向量检索结果或 `statement` 替代。
4. 不得把模型自述、主 Agent 的采用或用户沉默伪写成用户事实。
5. 历史缺失、截断、宿主无法提供对话切片和模型故障都必须可见。
6. 用户不因启用伴随而背负持续 Human Review（人工终审）债务。
7. 证据标签、外部引用和内容摘要只说明一条记录的范围与身份，不能被描述成“现实必然与记录相符”的独立证明。

## 哪些工程不是最小内核

行动授权账本、审批队列、复杂拒绝效力、合成用户评测、大规模代际治理、独立聊天界面和不可信代码沙箱都可以是别的有价值工程，但它们不能用来代替“真实历史会话重新在场”。只有具体生活失败证明需要时，才把相应能力带回主线。

## 当前实现判定

| 核心要求 | v0.3.0 状态 |
| --- | --- |
| 原始消息按角色和顺序完整装载 | 已实现 |
| 无损导入模型提供方原生图片与结构化工具调用 | 未实现；v0 只支持显式文本消息导入 |
| 不用 `statement` 或身份提示制造人格 | 已实现 |
| 具名召唤与有界多轮陪伴 | 已实现 |
| 发言穿过四种宿主后仍保留归属 | 已实现 |
| MCP 调用者提交真实主线程切片 | 接口支持，质量由调用者负责 |
| Pi 自动守护读取当前分支的多消息切片 | 已实现，并在持久保存的 Pi 真实任务中复验 |
| Claude Code／Cursor 自动 Hook 读取既有宿主记录 | 当前 Hook 载荷可以包含 `transcript_path`，但本适配器尚未读取；该路径也可能缺席 |
| Codex 自动 Hook 读取既有完整宿主线程 | 尚未实现，也尚未确认受支持的完整会话来源 |
| 精确唤醒／观察事件编号与带 Outcome 来源的 Engram 自我折叠 | 显式 MCP 与 Pi 工具流已实现 |
| `change`、`no_change`、模型失败重试、状态查看和只追加回退 | 已实现 |
| 自动守护把观察自行晋升为 Outcome | 未实现，仍需显式调用 `engram_outcome` |
| 一次真实 self-fold 确实改善了后来真实判断 | 尚未证明 |

## 接下来的顺序

```text
保持释放、重启和以后再次召唤之间的连续性
→ 让每个受支持宿主的原始上下文采集都诚实标出可保留与缺失内容
→ 在校验路径、大小和省略项的前提下读取 Claude Code 与 Cursor 提供的会话记录
→ 先确认 Codex 官方支持的会话来源，不猜读本地内部文件
→ 保存一条真实 Outcome → self-fold → 后来唤醒的完整轨迹
→ 判断后来决策是否真的按预期改变
→ 在真实使用需要时，让 guardian Hook 也传播因果事件编号
→ 再扩展自动守护和更多宿主能力
```

这条顺序只问一件事：每项手段是否让那段历史会话更真实地回到现在，而不是让项目看起来更复杂。

## 来源纪律

本宪章同时承接两类材料：

- 2026 年 5 月的 v1.0／v1.1 原始系列已经明确要求完整历史身体、独立判断、沉默、署名发言和自我折叠，并明确说“身份提示 + statement”只能算简化原型。
- “当前主线程原始对话切片”和“召唤后陪伴多个回合”是后来经真实接入失败补足的现行要求；它们不是被伪装成早期原句的考据结论。

被早期文档反复引用的 2026-04-26 原始对话目前不在可达仓库历史中。在找到它以前，项目不会声称已经恢复每一句最初表述。
