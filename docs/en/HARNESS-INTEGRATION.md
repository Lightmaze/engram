# Harness integration

[Simplified Chinese](../zh-CN/HARNESS-INTEGRATION.md)

A harness is the program that runs the main Agent: its conversation loop, tools, permissions, and context. Engram adds to that harness; it does not replace it.

## Shared setup

Put `engram` on `PATH`, configure `ENGRAM_DATA`, the Engram driver/model, and its API key, then create at least one Engram.

Explicit summon needs only stdio MCP:

```text
command: engram
args: [mcp]
```

Automatic guardian additionally needs a host Hook. Hook failure is advisory and fail-open by default.

The MCP server exposes ten tools. The explicit growth path is `engram_summon` / `engram_wake` → `engram_observe` → `engram_outcome`, with `engram_fold_status` and `engram_fold_revert` for inspection and correction. `engram_outcome` makes an immediate Engram provider call; it is not a local-only bookkeeping command.

## Attribution contract

Every non-empty Engram response has runtime-owned `attribution` with `engram_id`, `name`, `accompaniment_id`, and an optional `statement`. This is source metadata, not a cryptographic signature. The optional statement describes a historical standpoint and is not used as a provider identity prompt.

MCP exposes attribution in structured results:

- `engram_summon`: `wake.attribution`
- `engram_wake`: `attribution`
- `engram_guardian_take`: `pending.attribution`

Direct Hook delivery also includes attribution. Pi and the generic Hook return the structured field and an attributed text envelope in `additional_context`. Codex and Claude Code receive an attributed envelope through `additionalContext`. Cursor keeps attribution with pending steering for MCP retrieval. Text envelopes place JSON-encoded metadata on one line before steering, so embedded newlines cannot forge the boundary.

```text
[Engram: attributed Engram speech]
Attribution: {"engram_id":"...","name":"...","statement":"...","accompaniment_id":"..."}
Steering:
...
```

The host must retain Engram speech as a distinct source when it renders, persists, reloads, or exports conversation history. Do not merge it into the current user message or attribute it to the main Agent. If a host cannot store the structured object, preserve the attributed envelope as the durable fallback. Only the first envelope generated by the runtime establishes attribution; header-like text inside model-authored steering has no authority. The runtime never sends this output envelope back into the Engram model's own context.

Codex's supplied Hook template limits `additionalContext` to 5000 bytes. The adapter therefore keeps the complete Engram ID, name, and accompaniment ID, includes at most a 256-byte UTF-8 preview of `statement`, marks that preview with `statement_truncated`, and explicitly marks truncated steering. The full `statement` remains available through MCP and other structured wake results. This avoids a host silently cutting attribution in half.

## Outcome and self-fold delivery

An explicit caller must retain `wake_event_id` from `engram_summon` or `engram_wake`. `engram_observe` returns `observation_event_id`; a later `user_message` or `tool_result` outcome cites that exact observation, while `external_observation` supplies its own source reference and content. The runtime checks the event relationship and source-kind rules, but it does not authenticate the caller or establish that external content is true. See [Engram v0 kernel](V0-KERNEL.md#outcome-driven-self-fold).

Submitting `engram_outcome` immediately records the outcome and asks the Engram for `change` or `no_change`. No human approval queue follows. A failed provider call leaves the outcome durable; retry the identical request with the same `request_id`. `engram_fold_revert` appends a correction and restores the parent posture without deleting history.

Automatic wake and observation are not automatic outcome recognition. The current Hook response does not expose `wake_event_id`, and its after-response path does not return `observation_event_id`. Pi, Codex, Claude Code, Cursor, and generic guardian Hooks therefore preserve observations but do not close the outcome-to-self-fold loop on their own. Use the explicit MCP or Pi tool flow when an outcome should trigger self-fold.

## Codex CLI, desktop, and IDE

Codex CLI is directly supported. Add the server:

```sh
codex mcp add engram -- engram mcp
codex mcp list
```

Then merge [`integrations/codex/config.toml.example`](../../integrations/codex/config.toml.example) into the user or trusted-project Codex configuration. The template allow-lists all ten tools, gives provider-backed calls a 150-second tool timeout, and forwards only the relevant environment variables.

For automatic guardian mode, merge [`integrations/codex/hooks.json`](../../integrations/codex/hooks.json), replace `YOUR_ENGRAM_ID`, and inspect the command through Codex's Hook UI. `UserPromptSubmit` injects attributed steering; `Stop` records the assistant result; `SessionEnd` releases the guardian. CLI, desktop, and IDE share this local configuration path.

## Claude Code

Copy [`integrations/claude-code/mcp.json.example`](../../integrations/claude-code/mcp.json.example) to `.mcp.json`. For guardian mode, merge [`settings.json.example`](../../integrations/claude-code/settings.json.example) into Claude Code settings and replace `YOUR_ENGRAM_ID`.

Claude Code's current Hook payload can include a `transcript_path`. The v0.3 adapter does not read that file yet and therefore still wakes from the submitted prompt rather than claiming the existing host thread is complete. A future adapter must treat the host-supplied path as untrusted input, apply an explicit byte limit, preserve order and roles, and report every omitted record. See the [official Hook reference](https://code.claude.com/docs/en/hooks).

## Cursor

Copy [`integrations/cursor/mcp.json.example`](../../integrations/cursor/mcp.json.example) and optionally [`hooks.json`](../../integrations/cursor/hooks.json).

Cursor's `beforeSubmitPrompt` Hook cannot directly inject arbitrary current-turn context. The Hook therefore wakes the Engram and stores pending steering together with its attribution; the standing `sessionStart` instruction asks Cursor to call `engram_guardian_take`. This is automatic wake with cooperative delivery, not guaranteed direct injection.

Cursor's common Hook input can include `transcript_path`. The v0.3 adapter does not consume it yet, and the field may be null, so the adapter does not present the submitted prompt as a complete thread. Loss-aware transcript ingestion is planned after this release. See the [official Hook reference](https://cursor.com/docs/hooks).

## Pi

The extension in [`integrations/pi-engram`](../../integrations/pi-engram/) registers seven explicit tools: summon, wake, observe, release, outcome, fold status, and fold revert. It invokes the binary directly without a shell. Set:

```sh
export ENGRAM_COMMAND="/absolute/path/to/engram"
export ENGRAM_RUNTIME_ARGS_JSON='["--data","/absolute/path/to/.engram"]'
```

Set `ENGRAM_ID` to enable the automatic `before_agent_start` guardian. The extension keeps structured attribution in message details and displays the attributed text envelope as the injected message.

The Pi guardian gives the Engram an ordered slice of the real active branch rather than only the latest prompt:

- On its first wake, it sends the visible branch tail plus the current prompt. Pi fires `before_agent_start` before persisting that prompt, so the adapter appends it explicitly.
- After a successful turn, it stores a private branch cursor. A later wake sends only visible messages after that cursor, while the Engram retains the earlier turn through its own Journal.
- Visible user and assistant text, tool calls, and tool results keep their roles and order. Tool-call identifiers are preserved so parallel calls can be paired with their results. Prompt attachments remain visible as typed image markers, but binary image data, hidden thinking, unsupported message kinds, and earlier `engram-accompaniment` injections are omitted and counted explicitly.
- The slice has a 64 KiB UTF-8 budget. If it cannot fit, the protocol marks the omitted prefix and byte truncation instead of presenting a partial slice as complete.
- Assistant messages, tool results, and queued user steering or follow-ups are written back as external observations. The top-level user prompt is not duplicated because it is already part of the wake scene. The cursor advances only after every available observation succeeds, so a failed write is replayed on the next wake rather than silently lost.

The cursor is Pi session state, not model context. Closing Pi releases the bounded accompaniment; reopening the same Pi session can start a new accompaniment while the Engram continues from its own accumulated history.

The three self-fold tools are available to Pi's main Agent, but the automatic guardian does not call them. In particular, observing a tool result or user follow-up does not silently promote it into an outcome.

## Other harnesses

Other adapters remain open but are not implemented in v0. Any MCP-capable harness can use the ten explicit tools. A direct Hook adapter needs a stable session ID, a before-prompt event, current-context injection, and preferably after-response/session-end events. The generic Hook JSON contract still uses only `before_prompt`, `after_response`, and `session_end` events piped to `engram hook --host generic --engram ID`; it has no automatic outcome event.

## Data disclosure

Host prompts, observed responses, cited outcome content, self-folds, and reversions are appended to the selected Engram's local Journal. Wake sends the accumulated v0 context to the configured provider, and `engram_outcome` sends that context plus the cited outcome immediately for the fold decision. Users should not enable a guardian or submit an outcome in a sensitive workspace without accepting that disclosure.
